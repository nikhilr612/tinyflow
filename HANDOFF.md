## 1b. The end state (decided 2026-09-20, not started)

Once the experiments are done, pick **one winner** — model + architecture +
sampler recipe — and do an *equivalent, cleaner, tighter, smaller rewrite* on the
other unmerged branch (the one held to master's standard).  Not a merge of this
branch and not pruning in place: fresh minimal modules in the `toyfm` / `imagefm`
docstring style, none of the conditional paths built during exploration
(`cond_dropout`, dataset switches, `--image-size`, flow-map flags if the winner
does not use them, every experiment script; the indicator channel of the
conditioning token exists only for `cond_dropout > 0` and is a constant 1 in the
recipe — drop it, input = image + 3 mask channels).  The `justfile` shrinks to two
commands — train the toy model, train the best anime-faces model — plus at most
one recipe that renders showcase images from the best anime checkpoint.
Criteria: simplicity, correctness, cleanliness.  The model must run anywhere
and cheaply: low NFE (midpoint-8 is free; the MeanFlow map is the 1–2 NFE bet,
`runs/mf_rp_100`), then ONNX export + CPU latency numbers.  This branch keeps
every gory detail.

## 1c. Two debts to pay before the rewrite (added 2026-09-20)

**Reproducibility — of the rewrite.**  The acceptance test for the clean-branch
rewrite is that it *reproduces the winner*: train it from scratch with the same
seed and recipe and compare against the experiment-branch run it replaces —
the loss curve epoch by epoch, the final FID / iris numbers, and a paired
sample grid from the same noise.  To make that comparison tight rather than
"within ±4 FID", first establish on this branch how deterministic a run is:
same seed twice for 3 epochs, diff `losses.json` and the weights (GPU
convolutions and Grain worker threads are the usual sources; if they differ,
record the size of the drift, and use `XLA_FLAGS=--xla_gpu_deterministic_ops=true`
plus a single-threaded loader for the acceptance run if needed).  Then a second
seed of the final recipe at full length, both numbers reported.

**Training instability — never diagnosed.**  Four one-epoch divergences at
constant LR 1e-3 (anime RP ep 80, mid-attention ep 12, standard skips ep 3,
CelebA RP ep 25); the plain model never diverged; warm-up + cosine avoided it
without explaining it.  Facts: `clip_by_global_norm(1.0)` was already in the
optimiser (since 7ad2eed, before every event), so it is not a single large
gradient.  Leading hypothesis: Adam + zero-initialised modules — their second
moments start near zero and stay small while their gradients are tiny, so once
the gradient grows the normalised step is ~lr for many steps (clipping cannot
help; a lower lr does).  Cheapest reproduction: the CelebA-64 RP config at
constant 1e-3 diverges at ~5k steps (≈12 min).  Plan: (1) a diagnostic run
logging per step the pre-clip grad norm, the clip ratio, and per-module
update-norm / weight-norm and Adam `v` minimum (in_conv, blocks[i],
region_pools, time_mlp, out_conv), saving *raw* weights every epoch near the
event; (2) bisect: β2 0.999 → 0.99, eps 1e-8 → 1e-6, RP init zero → small
random, constant 5e-4; (3) write the answer into METHODS §3.2 and make the
winner's optimiser settings follow from it rather than from the schedule alone.

## 1f. Instability diagnosis — outcome (2026-09-20 evening; METHODS §3.2 to update)

`experiments/instability.py` reproduces the CelebA config with per-module Adam
telemetry.  60 epochs at peak 1e-3 on the original 100-epoch cosine did **not**
diverge (nor did 40 on a 40-epoch cosine): the event is stochastic.  Measured
preconditions: Adam second moments of the deepest block and the RegionPool
layers decay to 1e-13–1e-11 (√v ≫ ε, so steps are lr-sized regardless of
signal; relative update ~3e-3/step even late); gradients are heavy-tailed
(p99 15× median, max 160× at init).  A spike on such parameters is amplified up
to 1/√(1−β2) ≈ 32× lr and global-norm clipping cannot stop it.  Mechanism-level
fixes for the rewrite: cap the Adam update ratio, or β2 = 0.99; the recipe's
peak 5e-4 + warm-up + cosine is the empirical one.  Not bisected (no event to
bisect against).  Telemetry: `runs/instab/{base,cos40_nodiv}/telemetry.jsonl`.

## 1g. mask_input ablation (2026-09-20): masks through RegionPool only

**Confirmed and adopted** (METHODS §7.3): on `wide_rp_200`'s exact schedule,
stopped at epoch 125 (∑lr matched), `mask_input=0` gives FID 31.9 / 31.7 vs
32.9 / 31.4, iris 3.9–4.3 % (1.6 % on the 256-sample metric) vs 4.3 %.  The
winner's U-Net takes the image only; the layout enters through RegionPool.
Reference run for the rewrite's reproduction test: `runs/maskin/mi0_200s125`
(seed 49, 200-epoch cosine, stop at 125).  Lesson on horizons: compare runs at
matched ∑lr, not matched epochs — a 120-epoch cosine integrates ~60 peak-epochs
vs 85 for the 200-cosine at epoch 100, and trailed by 2–4 FID for that reason
alone.

## 3. Things you need to know that are not obvious from the code

- **Learning rate.** Constant 1e-3 diverges in one epoch on the 37M model once
  anything is added (four times now, incl. CelebA at epoch 25).  Warm-up + cosine
  is the default; `just celeba` bakes in 5e-4 / 2000-step warm-up.  If a run must
  be resumed, `--n-epochs` is the *remaining* epochs (the cosine is computed from
  it) and the resumed segment is its own schedule — say so in any write-up.
- **Use `best_model.eqx`**, not the final weights, for the conditioned model; the
  FID turning point is near epoch 125 of a 200-epoch cosine.
- **FID noise** at 30 epochs is ±4; loss is stable to ±0.0003.  Anything within
  5 FID needs a second seed or a longer horizon.
- **One GPU job at a time.**  A second job during an FID stage → OOM / cuSolver
  failure.  `XLA_PYTHON_CLIENT_MEM_FRACTION=0.47` if two must share.
- **Checkpoint compatibility.**  `UNet.from_hparams` ignores unknown keys, but
  the archive's anime checkpoints predate the nose channel / 4-channel masks —
  load them at tag `ckpt-9aef10c` if exact numbers matter (`runs/archive/9aef10c/README.md`).
  The sequential-RP checkpoint (`nodrop_rp`) differs from the parallel layer by
  mean |Δx̂| = 0.008.
- **Detector environment** (only for regenerating landmarks / mask-following
  scores): `~/.claude/jobs/211c1fe7/tmp/det/bin/python` — a scratch dir that can
  vanish; recipe: `anime_face_detector` (hysts), `cv2`, torch + CUDA.
- **`*.md` is gitignored** (since a578517) but the tracked ones (this file,
  README, METHODS, CELEBAMASK_SCOPE) stay tracked; `git add -f` for a new one.
- **Iris-mismatch metric** is validated but crude and uncorrelated with FID;
  always report both.
